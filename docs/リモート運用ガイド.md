# リモート運用ガイド — 手元のシェルから VM に LLM を立てて Codex で使う

Colab VM 上に Ollama + LLM を構築し、それを Codex CLI から使うまでの手順。
ブラウザは一度も開かない。

設計の背景と「なぜこうなっているか」は [手順書 §12](手順書.md)、
検討の経緯は [リモート化計画.md](リモート化計画.md)、実測値は
[../RESULT.md](../RESULT.md) にある。ここは**手を動かす順番だけ**を書く。

---

## 0. 一度だけやる準備

### 0.1 colab CLI を git から入れる

**PyPI 版（0.6.0）では駄目。** `colab ssh` は v0.7.0 で追加されたが、
PyPI にはまだ出ていない（2026-09-17 時点）。

```bash
uv tool install --force "git+https://github.com/googlecolab/google-colab-cli@v0.7.1"
colab version        # -> Version: 0.7.1
```

`uv` が無ければ `pip install "git+https://..."` でもよい。

### 0.2 SSH 鍵（ed25519）

**Colab 側は RSA 鍵を拒否する。** 無ければ作る。

```bash
ls ~/.ssh/id_ed25519 || ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519 -N ''
```

### 0.3 認証

既定は `oauth2`。初回だけブラウザでの認可が要る。

```bash
colab --auth=oauth2 sessions
```

`No active sessions found on server.` と出れば通っている。
トークンは `~/.config/colab-cli/token.json` にキャッシュされる。

<details>
<summary>ADC を使いたい場合（COLAB_AUTH=adc）</summary>

**スコープを 4 つ明示する必要がある。** 1 つでも欠けるとセッション確保か
キープアライブが 401/403 で落ちる。

```bash
gcloud auth application-default login \
  --scopes=openid,\
https://www.googleapis.com/auth/cloud-platform,\
https://www.googleapis.com/auth/userinfo.email,\
https://www.googleapis.com/auth/colaboratory
```

`colab auth` は**VM 側**に GCP 認証情報を入れる別のコマンド。
CLI の 401/403 の対処には使えない。
</details>

### 0.4 確認

```bash
cd /path/to/colab-ollama
bash remote/00_doctor.sh
```

**このスクリプトは VM を作らないので課金しない。** 最後に
`前提は揃っています。次: bash remote/01_new.sh` と出れば準備完了。

## 1. 毎回の流れ

```bash
bash remote/01_new.sh        # ① VM 確保（★ここから課金）
bash remote/02_deploy.sh     # ② スクリプトを VM へ送る
bash remote/03_setup.sh      # ③ Ollama + モデル + Codex（10〜20 分）
bash remote/04_attach.sh codex   # ④ Codex に入る
bash remote/09_stop.sh       # ⑤ ★成果物を回収して停止
```

### ① `01_new.sh` — VM 確保

T4 を確保し、ssh 経路を検証し、**GPU ライブラリのパスを直す**。
最後にこう出れば成功:

```
[   OK] nvidia-smi が環境変数なしで通るようになりました
      Tesla T4, 15360 MiB, 14913 MiB, 580.82.07
[   OK] Tesla T4 (sm_75)。bf16 非対応・FlashAttention2 非対応。GGUF 量子化前提で進めます。
```

> **なぜライブラリのパスを直すのか**
> Colab のノートブックカーネルは `LD_LIBRARY_PATH=/usr/lib64-nvidia` を
> 設定するが、**素の SSH ログインには引き継がれない**。放っておくと
> **Ollama が CUDA を検出できず、エラーも出さずに CPU へ落ちる**。
> 推論が一桁遅くなるだけで動いてしまうので、気付かないまま
> 「このモデルは遅い」と誤った結論を出すことになる。

別の GPU を試す場合（**無料枠では T4 しか引けない**）:

```bash
COLAB_GPU=L4 bash remote/01_new.sh
```

### ② `02_deploy.sh` — スクリプトを送る

手元の作業ツリーを丸ごと VM の `/content/colab-cline` へ送る。
`git clone` ではないので、**未コミットの変更もそのまま乗る**。
`.git` は送らないため、VM 側で git 操作はできない。

### ③ `03_setup.sh` — ここが本体

VM 上で `scripts/00_setup_all.sh --with-codex` を走らせる。中身は:

1. Ollama を導入して起動
2. **pull 前に VRAM に載るか判定**（載らなければ 13GB を落とす前に止まる）
3. ベースモデルを pull
4. `num_ctx` などを焼き込んだ**ラッパーモデル `cline-coder` を作る** ←★重要
5. VRAM にロードして**速度ベンチを取る**
6. Node 22 + Cline CLI
7. Codex CLI + `~/.codex/config.toml` + `AGENTS.md`

**VM 側では `nohup` で切り離して走る。** 手元の接続が切れても処理は続く。
見るのをやめたければ Ctrl-C してよく、もう一度同じコマンドを叩けば
走っているものに合流する（二重起動はしない）。

終わるとベンチ結果が出る。**この数字を見てからモデルを決める**:

```
      prompt eval        : 10282 tok / 11.7s = 880 tok/s
      generation         : 256 tok / 7.4s = 34.5 tok/s
      ★ 安全に投げられるプロンプト長 : 約 13,645 トークン
      判定: OK
```

## 2. Codex から使う

### 2.1 ★ Codex に出てくるモデル名は常に `cline-coder`

**ここが一番はまる。**

`03_setup.sh` は `BASE_MODEL`（例 `gpt-oss:20b`）をそのまま使わない。
`num_ctx` / `num_predict` / temperature を焼き込んだ**ラッパーモデル**を
`ollama create` で作り、それに `cline-coder` という名前を付ける。
`~/.codex/config.toml` の `model` もこの名前を指す。

したがって **Codex の起動画面や `/model` の一覧に `gpt-oss:20b` は出てこない。**
`BASE_MODEL` を変えても表示名は `cline-coder` のままで変わらない。

**選ぶべきモデル名は常に `cline-coder`。** 実体を確認したいときは:

```bash
bash remote/common.sh -c 'ollama show cline-coder | head -20'
bash remote/common.sh -c 'ollama list'
```

### 2.2 対話 TUI

```bash
bash remote/04_attach.sh codex
```

`/content/workspace` で `codex` が起動する。
ここは `30_cline_cli.sh` が `git init` した作業用ディレクトリで、
`AGENTS.md`（モデル別の運用ルール）が置かれている。

### 2.3 非対話（評価やスクリプト用）

```bash
bash remote/04_attach.sh -- 'cd /content/workspace && codex exec "fizzbuzz.py を作って実行して"'
```

実測例（gpt-oss:20b、2026-09-17）: 1 往復で `fizzbuzz.py` を書き、
`ls -la && cat` で自己確認し、`python3` で実行して日本語で報告するところまで完走した。

### 2.4 ただのシェルとして使う

```bash
bash remote/04_attach.sh                      # 対話シェル
bash remote/04_attach.sh -- 'nvidia-smi'      # 1 コマンド実行
bash remote/common.sh -c 'ollama ps'          # 同上（短縮形）
```

生成される `remote/.ssh_config` は普通の OpenSSH 設定なので、
`ssh` / `scp` / VS Code の Remote-SSH もそのまま使える:

```bash
ssh  -F remote/.ssh_config colab-vm
scp  -F remote/.ssh_config ./foo.py colab-vm:/content/workspace/
```

VS Code の Remote-SSH で使う場合は、`remote/.ssh_config` の中身を
`~/.ssh/config` に貼り付ける。

## 3. モデルを差し替える

`MODEL_PROFILE` を渡すだけでよい。`BASE_MODEL` / `NUM_CTX` / KV サイズ /
修復プロキシの有無 / `AGENTS.md` の中身がまとめて切り替わる。

```bash
MODEL_PROFILE=gpt-oss-20b bash remote/03_setup.sh
```

| プロファイル | モデル | T4 実測 |
|---|---|---|
| `qwen3-8b` | `qwen3:8b`（従来の既定） | ◎ 7.5GB / 生成 23.6 tok/s |
| `qwen3-14b` | `qwen3:14b` | ◎（未測定） |
| **`gpt-oss-20b`** | `gpt-oss:20b`（MXFP4 MoE） | **◎ 12.5GB / 生成 34.5 tok/s** |
| `qwen25-coder-14b` | `qwen2.5-coder:14b` | 不具合の再現用（§5.8.1） |

**いまのところ `gpt-oss-20b` が一番速い。** 20B だが MoE（活性 3.6B）なので
8B モデルより生成が 1.46 倍速く、ツール呼び出しも安定していた。

プロファイルを使わず直接指定することもできる（**明示指定のほうが優先される**）:

```bash
BASE_MODEL=qwen3:14b NUM_CTX=8192 bash remote/03_setup.sh
```

載らないモデルを指定した場合は **pull の前に**止まる:

```
      必要量       :    16392 MiB (16.01 GiB)
      空き VRAM    :    14913 MiB (14.56 GiB)
      判定: NG — 1479 MiB 足りません。
```

どうしても試すなら `FORCE_VRAM=1`（層が CPU にあふれて極端に遅くなる）。

## 4. 中断・再開

**VM はステートレス。最長 12 時間、`colab stop` を忘れると 24 時間課金が続く。**

| やりたいこと | コマンド |
|---|---|
| いま VM が生きているか | `colab --auth=oauth2 sessions` |
| セットアップの進捗を見直す | `bash remote/03_setup.sh`（走行中なら合流する） |
| 手元のスクリプトを直して送り直す | `bash remote/02_deploy.sh` |
| VM 上のファイルを取り出す | `bash remote/09_stop.sh`（停止前に自動回収） |

`01_new.sh` は既存セッションがあれば作り直さないので、
中断後にもう一度叩いても安全。

**VM 上で書いたコードは `09_stop.sh` が `artifacts/` に回収する。**
それ以外の方法で残したければ手元へ `scp` するか、VM 上で git push する。

## 5. トラブルシュート

| 症状 | 原因と対処 |
|---|---|
| `colab ssh` が無い | PyPI 版（0.6.0）が入っている。§0.1 で git から入れ直す |
| ssh で `Permission denied` | 鍵が RSA。**Colab は ssh-rsa を拒否する**。§0.2 で ed25519 を作る |
| `colab sessions` が 401 | トークン期限切れ。`colab --auth=oauth2 sessions` で取り直す |
| `colab sessions` が 403 | ADC のスコープ不足。§0.3 の 4 スコープで取り直す |
| `colab new` が 400 | そのアクセラレータの割り当てが無い。**無料枠は T4 のみ** |
| `nvidia-smi` が `libnvidia-ml.so` で失敗 | §1 ① の ldconfig。`01_new.sh` が自動でやる |
| **推論が異常に遅い** | **Ollama が CPU に落ちている。** 下の確認コマンドを見る |
| Codex に `gpt-oss:20b` が出ない | 仕様。**選ぶ名前は常に `cline-coder`**（§2.1） |
| 15GB 落としてから載らないと分かる | 起きないはず。起きたら事前チェックが飛ばされている |

**「Ollama が GPU を使っているか」の確認** — これは必ず見ること:

```bash
bash remote/common.sh -c 'ollama ps'
#   PROCESSOR 列が "100% GPU" であること。"CPU" や "50%/50%" なら失敗

bash remote/common.sh -c 'grep "inference compute" /content/logs/ollama.log | tail -1'
#   library=CUDA compute=7.5 name=CUDA0 description="Tesla T4" が出ること
```

ログの置き場所:

| 中身 | 場所（VM 上） |
|---|---|
| セットアップ全体 | `/content/logs/setup.log` |
| Ollama | `/content/logs/ollama.log` |
| ベンチ結果 | `/content/.cline-env/bench-summary.txt` |
| VRAM 事前チェック | `/content/.cline-env/vram-precheck.json` |

## 6. 片付け（必須）

```bash
bash remote/09_stop.sh
```

`logs/` `.cline-env/` `workspace/` を `artifacts/<セッション名>-<日時>/` へ
回収してから停止する。最後にこう出れば課金は止まっている:

```
[   OK] 停止しました。課金は止まっています。
```

回収せずに即停止するなら `--no-fetch`。

**止め忘れがこの構成でいちばん高くつく事故。** 疑わしいときは:

```bash
colab --auth=oauth2 sessions     # -> "No active sessions found on server."
```
